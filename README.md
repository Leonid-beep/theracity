# TheraCity

TheraCity — веб-приложение о городе как пространстве для самонаблюдения, визуального исследования и арт-терапевтической практики. Проект объединяет фотогалерею городских мест, систему маршрутов и личный кабинет пользователя, где можно собирать избранное и составлять собственные подборки.

Сайт построен вокруг идеи, что городской ландшафт может быть не только фоном, но и инструментом эмоционального отклика. Пользователь изучает фотографии, фильтрует их по настроению и атмосфере, сохраняет понравившиеся места и собирает из них маршруты.

## Что умеет сайт

- Просмотр фотогалереи с фильтрацией по метро, типу пространства, эмоциональному фону и атмосфере.
- Открытие фото в модальном окне с навигацией по всему отфильтрованному разделу.
- Добавление фотографий в избранное.
- Создание маршрутов из выбранных фотографий.
- Просмотр опубликованных маршрутов других пользователей.
- Открытие маршрута в модальном окне с навигацией по всему списку маршрутов раздела.
- Добавление маршрутов в избранное.
- Публикация и шаринг собственных маршрутов.
- Личный кабинет с тремя зонами: мои маршруты, избранные фото, избранные маршруты.
- Регистрация, вход, выход и восстановление пароля по email.
- Админские действия: загрузка, редактирование и удаление фотографий.

## Основные разделы

- `/start` — стартовый экран проекта.
- `/gallery` — фотогалерея с фильтрами, модалкой фото и созданием маршрутов.
- `/routes` — каталог пользовательских маршрутов.
- `/cabinet` — личный кабинет.
- `/about` — описание идеи и назначения проекта.
- `/auth/login` и `/auth/register` — авторизация и регистрация.

## Роли пользователей

### Гость

- Может просматривать галерею и маршруты.
- Может пользоваться фильтрами.
- Не может сохранять избранное и создавать маршруты без авторизации.

### Авторизованный пользователь

- Может добавлять фото и маршруты в избранное.
- Может создавать маршруты.
- Может публиковать и удалять собственные маршруты.
- Получает доступ к личному кабинету.

### Администратор

- Имеет все права обычного пользователя.
- Может загружать новые фотографии.
- Может редактировать и удалять фотографии.
- Администратор определяется по `ADMIN_EMAIL`.

## Технологии и стек

### Frontend

- `Next.js 16` с `App Router`
- `React 19`
- `TypeScript`
- CSS Modules
- Динамические модальные компоненты через `next/dynamic`

### Backend

- Route Handlers в `app/api/**`
- `Prisma` как ORM
- `PostgreSQL`
- Cookie-based JWT-сессии через `jose`
- `bcrypt` для хеширования паролей
- `nodemailer` для восстановления пароля

### Хранение медиа

- S3-совместимое объектное хранилище
- В текущей конфигурации проект ориентирован на Yandex Object Storage

## Архитектура проекта

- `app/` — страницы, layout'ы, API route handlers и UI-логика.
- `app/api/` — серверные обработчики для авторизации, фотографий, маршрутов, фильтров и избранного.
- `app/gallery/` — галерея и связанные модальные окна.
- `app/routes/` — публичные маршруты и модалка маршрута.
- `app/cabinet/` — кабинет пользователя.
- `app/lib/` — Prisma, auth, S3, вспомогательные функции.
- `app/ui/` — общие UI-компоненты.
- `prisma/` — схема БД, миграции и сиды.
- `public/` — статические изображения, иконки и ассеты.

## Модель данных

В базе данных используются следующие основные сущности:

- `User` — пользователь.
- `Photo` — фотография с метаданными.
- `Route` — маршрут пользователя.
- `RoutePhoto` — связь маршрута и фотографии с порядком.
- `FavoritePhoto` — избранные фотографии пользователя.
- `FavoriteRoute` — избранные маршруты пользователя.
- `PasswordReset` — коды восстановления пароля.

Фотография хранит:

- заголовок;
- метро;
- координаты;
- тип пространства;
- настроение;
- атмосферу;
- ссылку на объект в S3.

## Ключевые пользовательские сценарии

### Работа с галереей

- Пользователь заходит в галерею.
- Выбирает один или несколько фильтров.
- Открывает фотографию.
- Листает все фото текущего отфильтрованного раздела в модалке.
- Сохраняет фото в избранное или добавляет его в маршрут.

### Работа с маршрутами

- Пользователь открывает раздел маршрутов.
- Фильтрует список маршрутов по тем же параметрам.
- Открывает маршрут.
- Листает маршруты всего текущего раздела в модалке.
- Внутри маршрута переключается между фотографиями маршрута.
- Делится ссылкой на маршрут или сохраняет его в избранное.

### Работа в кабинете

- Пользователь смотрит свои маршруты.
- Публикует маршрут.
- Управляет избранными фотографиями и маршрутами.
- Удаляет созданные маршруты.

## Переменные окружения

См. файл [`.env.example`](./.env.example).

### Обязательные

- `DATABASE_URL` — строка подключения к PostgreSQL.
- `JWT_SECRET` — секрет для подписи JWT.
- `S3_ENDPOINT` — endpoint S3-хранилища.
- `S3_REGION` — регион хранилища.
- `S3_ACCESS_KEY` — access key.
- `S3_SECRET_KEY` — secret key.
- `S3_BUCKET` — имя bucket.
- `ADMIN_EMAIL` — email администратора.

### Опциональные

- `AUTH_COOKIE_SECURE` — ручное управление флагом `Secure` у auth-cookie.
- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_USER`
- `SMTP_PASS`

## Быстрый старт локально

### 1. Установка зависимостей

```bash
npm install
```

### 2. Создание `.env`

Скопируйте значения из `.env.example` в локальный `.env` и заполните их под свою среду.

### 3. Генерация Prisma Client

```bash
npm run prisma:generate
```

### 4. Применение миграций

Для локальной разработки:

```bash
npm run db:migrate
```

Для production:

```bash
npm run prisma:migrate:deploy
```

### 5. Запуск приложения

```bash
npm run dev
```

Обычно сайт поднимется на:

```text
http://localhost:3000
```

## Production-сборка

```bash
npm run build
npm run start
```

Если production-сервер запускается локально без HTTPS и возникают проблемы с cookie-сессией, может понадобиться:

```env
AUTH_COOKIE_SECURE=false
```

## Доступные npm-скрипты

- `npm run dev` — запуск в режиме разработки.
- `npm run build` — генерация Prisma Client и production build Next.js.
- `npm run start` — запуск production-сборки.
- `npm run lint` — запуск ESLint.
- `npm run prisma:generate` — генерация Prisma Client.
- `npm run prisma:migrate:deploy` — применение production-миграций.
- `npm run db:migrate` — создание и применение миграции в dev.
- `npm run db:seed` — заполнение базы стартовыми данными.
- `npm run db:reset` — полный сброс базы с миграциями.

## Подготовка PostgreSQL

- Создайте базу данных PostgreSQL.
- Укажите корректный `DATABASE_URL`.
- Для облачной БД при необходимости добавьте `sslmode=require`.
- После этого выполните миграции Prisma.

Пример:

```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/DATABASE?schema=public"
```

## Подготовка S3-хранилища

- Создайте bucket.
- Выпустите ключи доступа.
- Укажите `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`.
- Убедитесь, что у ключей есть права на чтение, запись и удаление объектов.

## Что важно знать о проекте

- Фильтры в галерее и маршрутах работают независимо: для поиска достаточно выбрать хотя бы одну опцию.
- Модалка фото листает не только текущую страницу сетки, а весь отфильтрованный раздел.
- Модалка маршрутов также работает по всему отфильтрованному списку маршрутов.
- Внутри маршрута отдельно листаются фотографии самого маршрута.
- Права администратора завязаны на email, указанный в `ADMIN_EMAIL`.

- SMTP, если нужно восстановление пароля.

После первого деплоя стоит проверить:

- регистрацию и вход;
- загрузку галереи;
- открытие фото и маршрутов в модалках;
- работу избранного;
- создание и публикацию маршрута;
- доступ администратора к загрузке фото.
